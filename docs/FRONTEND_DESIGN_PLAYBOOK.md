# 자연스러운 서비스 UI 플레이북

이 문서는 Weather 프로젝트를 다듬으며 반복해서 확인한 원칙을 다음 프런트엔드 작업에서도 재사용하기 위한 체크리스트다. 목표는 장식이 많은 시안이 아니라, 정보의 우선순위와 상태 변화가 자연스럽게 읽히는 실제 서비스 화면이다.

## 1. 먼저 지킬 것

- 이미 완성된 화면의 시각 언어를 기준으로 삼는다. 새 화면도 같은 색 토큰, 선 굵기, 모서리, 여백 단위를 사용한다.
- 한 화면에 주인공은 하나만 둔다. 날씨 화면은 현재 날씨, 여행 화면은 여행지와 날짜 선택이 첫 번째다.
- 데이터가 없는 상태, 로딩, 실패, 권한 거부를 정상 화면과 같은 수준으로 디자인한다.
- 설명 문장은 기능을 이해하는 데 필요한 만큼만 남긴다. 개발 과정, API 이름, 구현 사정은 사용자 화면에 쓰지 않는다.
- 실제 데이터와 추정값을 구분한다. 예보, 과거 기후 참고, AI 가공 결과는 서로 다른 라벨을 사용한다.

## 2. AI처럼 보이기 쉬운 패턴

다음 패턴이 여러 개 겹치면 자동 생성 시안처럼 보이기 쉽다.

- 모든 정보를 각각 둥근 카드에 넣기
- 모든 버튼을 알약 모양으로 만들기
- 의미 없이 영문 대문자 라벨과 긴 설명을 반복하기
- 서로 다른 채도의 그라데이션을 섹션마다 추가하기
- 이모지나 정체를 알 수 없는 장식 기호를 아이콘 대신 쓰기
- 제목, 부제, 보조 설명, 배지까지 같은 내용을 네 번 말하기
- 실제 우선순위와 관계없이 모든 요소에 그림자와 호버 이동을 넣기

목록은 선과 여백으로 구분하고, 카드는 독립된 작업 단위에만 사용한다. 강조는 색, 크기, 굵기 중 한두 가지만 선택한다.

## 3. 제목과 줄바꿈

한 줄이어야 하는 핵심 문장은 구현 전에 가장 좁은 목표 화면에서 실제 문구로 검증한다.

- 제품 문구에 임의의 `<br>`를 먼저 넣지 않는다. 화면 폭이 바뀌면 어색한 두 줄이 고정된다.
- 반드시 한 줄이어야 하면 컨테이너 폭, 글자 크기, 좌우 여백을 함께 조정하고 `white-space: nowrap`을 명시한다.
- `text-wrap: balance`는 여러 줄 제목을 고르게 만들 때만 쓴다. 한 줄 문구에 적용하면 예상 밖의 줄바꿈을 만들 수 있다.
- 긴 본문은 `text-wrap: pretty`와 읽기 좋은 최대 너비를 사용한다.
- 여러 줄 한국어 상태 문구에는 `word-break: keep-all`과 `overflow-wrap: break-word`를 함께 써서 `없습니 / 다`, `잠 / 시`처럼 어절이 잘리는 현상을 막는다.
- 한국어 조사나 짧은 어절이 혼자 다음 줄에 남지 않는지 확인한다.
- 320px, 390px, 768px, 1280px 이상에서 실제 문구를 직접 확인한다.
- 글자를 무조건 줄이는 것으로 해결하지 않는다. 먼저 불필요한 문구와 과한 좌우 패딩을 줄인다.

예: `지금 있는 곳의 날씨부터 볼까요?`처럼 하나의 질문으로 읽혀야 하는 문장은 데스크톱 목표 화면에서 한 줄을 보장하고, 아주 좁은 모바일에서만 자연스러운 줄바꿈을 허용한다.

## 4. 투명 재질

글래스 효과는 배경을 보여주는 재질이지 흰색 반투명 카드의 별칭이 아니다.

- 배경색은 현재 테마 색과 섞고 `backdrop-filter`는 한 계층에만 적용한다.
- 테두리는 텍스트 색을 10~18% 정도 섞어 재질의 경계만 보여준다.
- 서랍과 내비게이션처럼 이어지는 요소는 접점의 테두리와 모서리를 제거해 하나의 물체로 보이게 한다.
- 투명 패널 안에 다시 투명 패널을 겹치지 않는다. 내부 항목은 리스트와 구분선으로 정리한다.
- 어두운 영상 위에서는 텍스트 대비를 실제 프레임별로 확인한다.

## 5. 테마와 대비

고정된 흰색·검은색보다 의미 기반 토큰을 사용한다.

- `--hero-text`: 핵심 텍스트와 주요 버튼 면
- `--hero-muted`: 보조 텍스트
- `--hero-start`, `--hero-end`: 장면 배경과 주요 버튼의 반대색
- `--weather-accent`: 날씨 아이콘, 현재 선택, 짧은 강조

주요 버튼은 `background: var(--hero-text)`와 `color: var(--hero-start)` 조합을 기본으로 한다. 상위 요소의 `color: inherit`가 버튼 글자를 덮지 않는지 특이도까지 확인한다. 비활성 상태도 글자와 면이 구분돼야 한다.

## 6. 내비게이션과 서랍

- 메뉴 수는 실제 서비스 구조만 반영한다. 로그인 전후에 같은 자리를 `로그인`과 `내 여행`으로 교체하면 항목을 늘리지 않아도 된다.
- 활성 상태는 큰 캡슐보다 작은 점, 선, 굵기처럼 조용한 신호를 우선한다.
- 하단 내비게이션 위로 열리는 서랍은 별도 카드가 아니라 내비게이션의 확장으로 보이게 한다.
- 스크롤 콘텐츠는 검색 영역 뒤로 지나가며 블러되게 하고, 위아래 여백 때문에 목록이 갑자기 끊기지 않게 한다.
- 장식용 스크롤바가 재질과 맞지 않으면 숨기되 키보드와 터치 스크롤은 유지한다.

## 7. 목록과 카드

- 도시, 예보, 상세 지표처럼 반복되는 정보는 기본적으로 한 줄 목록과 구분선을 사용한다.
- 둥근 카드는 로그인 폼, 여행 플래너처럼 독립된 작업 흐름 하나를 묶을 때만 사용한다.
- 한 행에서 정렬 기준을 고정한다. 이름, 상태, 수치, 행동의 열이 항목마다 흔들리지 않아야 한다.
- 국기는 펄럭이는 이모지 대신 작은 정적 원형 마크나 이미지 자산을 사용하고, 장식일 경우 스크린리더에서 숨긴다.

## 8. 아이콘과 움직임

- 아이콘은 같은 stroke 굵기와 viewBox 규격을 쓴다. 이모지와 선형 SVG를 섞지 않는다.
- 구름, 비, 햇빛, 눈은 동일한 단색으로 고정하지 말고 날씨 의미에 맞는 제한된 팔레트를 사용한다.
- 날씨 아이콘은 옆의 상태 문구나 온도 수치와 시각적 무게가 비슷해야 한다. 기준선이 어긋나면 크기를 키우기보다 `translateY`를 1~3px 조정한다.
- 정보 아이콘에 반복적인 부유·확대 호버를 넣지 않는다. 새로고침, 열기처럼 행동을 설명하는 움직임만 남긴다.
- 브라우저 기본 날짜 팝업은 내부 디자인을 안정적으로 바꿀 수 없다. 서비스 달력으로 교체할 때는 모양뿐 아니라 최소·최대 날짜, 범위 제한, 방향키, `Escape`, 포커스, 모바일 터치 영역까지 함께 구현한다.
- 분할 선택의 움직임은 각 버튼이 튀는 효과보다 하나의 선택 면이 다음 위치로 미끄러지는 방식이 상태 변화를 더 분명하게 보여준다.
- `prefers-reduced-motion`과 데이터 절약 모드에서는 배경 영상과 비필수 애니메이션을 끈다.

## 9. 상태 문구와 한국어

- 도시명 뒤 조사는 받침 여부를 계산한다. `서울이 선택되었습니다`, `DUBAI가 선택되었습니다`처럼 표시한다.
- 로딩 문구는 현재 진행 중인 한 가지 행동만 말한다.
- 실패 문구에는 사용자가 할 수 있는 다음 행동이 있을 때만 버튼을 둔다.
- 권한 안내의 주요 버튼과 보조 버튼은 모든 날씨 테마에서 대비를 확인한다.
- 영문 대문자 라벨은 짧은 분류 표식으로만 쓰고, 핵심 의미는 한국어 제목에 둔다.

## 10. 외부 데이터와 AI

- 좌표, 날짜, 날씨처럼 검증 가능한 사실은 전용 API가 결정한다. LLM이 지명이나 수치를 만들게 하지 않는다.
- 자유 입력 도시는 먼저 지오코딩으로 실제 위치를 확정한다.
- AI 웹 검색 결과를 사용하면 출처 링크를 눈에 보이고 클릭 가능하게 제공한다.
- 예보 범위를 벗어난 날짜에는 과거 기후 자료를 `기후 참고`로 표시하고 예보라고 부르지 않는다.
- API 키는 브라우저 번들에 넣지 않는다. 비밀키가 필요한 호출은 서버나 Edge Function에서 수행한다.
- AI 실패가 핵심 날씨 조회까지 막지 않도록 기능을 분리한다.
- 많은 도시·장소를 보여주는 화면도 첫 진입부터 전부 요청하지 않는다. 주인공 데이터만 먼저 받고 목록은 열었을 때 지연 로딩한다.
- 다중 좌표를 HTTP 한 번으로 묶어도 API 할당량은 항목 수만큼 가중될 수 있다. 네트워크 요청 횟수와 서비스 사용량을 같은 값으로 가정하지 않는다.
- 캐시에는 실제 성공 응답과 관측 시각만 저장하고 만료 시간을 둔다. 실패했을 때 임의 수치로 채우지 않으며 `Request failed with status code 429` 같은 전송 계층 문구를 사용자 화면에 그대로 노출하지 않는다.

## 11. 배경 영상

- 날씨 화면 영상은 실제 지역 중계가 아니라 날씨 상태를 보조하는 장면으로 사용한다.
- 여행지 영상은 `현재 모습`처럼 오해시키지 않고 목적지 분위기 자산으로만 사용한다.
- 파일마다 원본 URL, 제작자, 라이선스, 내려받은 날짜를 매니페스트에 기록한다.
- 첫 프레임, 중간 프레임, 마지막 프레임을 확인해 날씨와 맞지 않는 장면이나 노출 변화가 없는지 본다.
- 짧은 반복 구간, 적절한 비트레이트, 포스터 또는 색상 폴백을 제공한다.

## 12. 완료 기준

코드가 빌드되는 것과 화면이 완성된 것은 다르다.

1. 단위 테스트, 린트, 포맷, 프로덕션 빌드를 통과한다.
2. 모바일과 데스크톱에서 핵심 경로를 실제 브라우저로 확인한다.
3. 로딩, 빈 상태, 오류, 비로그인, 로그인 상태를 각각 확인한다.
4. 키보드 포커스 순서, 포커스 표시, 버튼 이름, 색 대비를 확인한다.
5. 네트워크 실패 시 핵심 기능이 남는지 확인한다.
6. 사용하지 않는 라우트, 컴포넌트, CSS, 환경변수, 설명 문구를 삭제한다.
7. 외부 자산과 API의 출처·설정·검증하지 못한 범위를 문서에 남긴다.
